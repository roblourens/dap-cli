## Accomplishments

- Added `dap.startCompound` to the controller request schema and server dispatch.
- Refactored DAP startup so single-session and compound-member launches share the same adapter lifecycle logic.
- Implemented serial compound startup with derived member names like `Compound/Server` and Plan 03 compound metadata.
- Added startup failure cleanup that terminates/removes already-started members and removes failed partial records.
- Wired CLI `launch --workspace <dir> --config <compound>` into `dap.startCompound`.
- Added `compound_member_not_found` preflight before opening controller IPC.
- Implemented `sessions.close` cascade across compound peers when `stopAll` is true/default, while preserving peers when false.

## Decisions Made

- Compound result shape is `{ compoundId, name, stopAll, members }`, where each member preserves normal `DapStartResult` fields.
- Compound-level `--name` is ignored for launch.json compounds; the compound name from launch.json is the group name, matching VS Code behavior and Plan 04 expectations.
- Member launch mode comes from the member configuration `request` when present, otherwise the invoked CLI command mode is used.
