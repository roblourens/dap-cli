## Deviations from Plan

### Auto-fixed Issues

**1. Built-in adapter type normalization happened too early**
- **Found during:** Real VS Code compound UAT
- **Issue:** The `VS Code` launch config selected js-debug, but the final merged config still carried legacy `type: "chrome"`, causing js-debug `Unknown config`.
- **Fix:** Added `mapConfigForAdapter` so js-debug/debugpy normalization runs on the final merged config for both single and compound launches.
- **Verification:** Real VS Code compound launch reached five running members.
- **Committed in:** `f7668b8`

**2. Real VS Code launch exceeded fixture-sized timeouts**
- **Found during:** Real VS Code compound UAT
- **Issue:** The CLI controller request timed out at 5s, then the controller lifecycle launch stage timed out at 10s on slower real workbench startup.
- **Fix:** Added a 60s start IPC timeout and aligned controller DAP request/lifecycle startup budgets at 30s.
- **Verification:** Fresh `npx dap-cli launch --config "VS Code" --workspace /Users/roblou/code/vscode` passed.
- **Committed in:** `f7668b8`

**3. stopAll close was serial and too slow for five VS Code members**
- **Found during:** Real VS Code compound UAT
- **Issue:** Closing the compound leader hit the 30s close client timeout while tearing down five members.
- **Fix:** Terminated compound member runtimes concurrently and raised close IPC timeout to 60s.
- **Verification:** Closing `VS Code/Launch VS Code Internal` returned `orphanPids: []`, `warnings: []`, and subsequent sessions output was empty.
- **Committed in:** `f7668b8`
