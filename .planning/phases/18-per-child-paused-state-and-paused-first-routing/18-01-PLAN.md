<objective>
Make `dap-cli status --name <parent>` reflect the union of child paused
state across multi-child js-debug attaches, and make `--thread-id`
routing prefer the child that is actually paused. After this plan,
the S-02 scenario (extension-host bp fires inside a child while a
bootloader sibling later terminates) reports `paused: true` on the
parent, and `dap-cli stack --name <parent>` against the paused thread
id returns the right frames without the agent ever needing to know a
child exists.

Two narrow bugs in the existing infrastructure (see CONTEXT.md):

  Bug A: parent paused-state is "last child event wins" — a bootloader's
         `terminated` clobbers the real child's `stopped`.
  Bug B: `findChildOwningThread` picks the first child whose thread
         cache claims the id, regardless of whether that child is
         actually paused.

Both are fixed inside `ChildSessionCoordinator`. No new flags, no
virtual thread ids, no new CLI surface.

Output: focused controller change + unit tests + fake-adapter
integration test + Code OSS hand-driven repro.
</objective>

    ```ts
    export interface ChildPausedSnapshot {
      stoppedThreadIds: ReadonlySet<number>;
      allThreadsStopped: boolean;
      knownThreadIds: ReadonlySet<number>;
      lifecycleEnded: boolean;
      lastStoppedReason: string | undefined;
    }

    export function combineChildPausedStates(snapshots: Iterable<ChildPausedSnapshot>):
      | { paused: false }
      | { paused: true; stoppedReason: string; stoppedThreadIds: readonly number[] } {
      const stopped = new Set<number>();
      let lastReason: string | undefined;
      for (const s of snapshots) {
        if (s.lifecycleEnded) continue;
        if (s.allThreadsStopped) {
          for (const id of s.knownThreadIds) stopped.add(id);
        } else {
          for (const id of s.stoppedThreadIds) stopped.add(id);
        }
        if (s.lastStoppedReason !== undefined && s.stoppedThreadIds.size > 0) {
          lastReason = s.lastStoppedReason;
        }
      }
      if (stopped.size === 0) return { paused: false };
      return { paused: true, stoppedReason: lastReason ?? 'unknown', stoppedThreadIds: [...stopped] };
    }
    ```

    ```ts
    private async findChildOwningThread(threadId: number): Promise<ChildRuntime | undefined> {
      // Pass 1: prefer a non-terminated child that is actually stopped on this thread.
      for (const child of this.children.values()) {
        if (child.lifecycleEnded) continue;
        if (child.stoppedThreadIds.has(threadId)) return child;
        if (child.allThreadsStopped && child.knownThreadIds.has(threadId)) return child;
      }
      // Pass 2: any non-terminated child that knows the thread.
      for (const child of this.children.values()) {
        if (child.lifecycleEnded) continue;
        if (child.knownThreadIds.has(threadId)) return child;
      }
      // Pass 3: cold path — live threads fan-out (only non-terminated).
      const live = [...this.children.values()].filter(c => !c.lifecycleEnded);
      const refreshes = live.map(async child => {
        try {
          const response = await child.client.request<{ threads?: Array<{ id: number; name: string }> }>('threads');
          for (const thread of response?.threads ?? []) {
            child.knownThreadIds.add(thread.id);
            if (typeof thread.name === 'string') child.threadNames.set(thread.id, thread.name);
          }
        } catch { /* per-child failure ignored */ }
      });
      await Promise.allSettled(refreshes);
      // Re-run passes 1–2 against refreshed cache.
      for (const child of live) {
        if (child.stoppedThreadIds.has(threadId)) return child;
        if (child.allThreadsStopped && child.knownThreadIds.has(threadId)) return child;
      }
      for (const child of live) {
        if (child.knownThreadIds.has(threadId)) return child;
      }
      return undefined;
    }
    ```

Threats considered:
- T-18-01: Child emits malformed `stopped` body (e.g. `threadId: 'abc'`). Mitigation: typeof-number guards on every body field read, matching the existing `derivePausedStateFromStopped` style.
- T-18-02: Child resurrects after `terminated` (re-emits `stopped`). Mitigation: clearing `lifecycleEnded = false` on a fresh `stopped` is safe — there is no security boundary here, only a state-correctness one. Add a comment noting the resurrection path.
- T-18-03: Spammed `stopped` events from a malicious adapter could grow `stoppedThreadIds` unboundedly. Mitigation: the set is bounded by the child's `knownThreadIds`, which is itself bounded by `threads` responses + thread events; same de-facto bound as today.
- T-18-04: `recomputeParentPausedState` calls `updatePausedState` on every event (vs today's narrower trigger). Mitigation: the calls are already async-fire-and-forget, and the SessionManager's persist is debounced — no perf concern at child event rates we observe (~10s of events per second worst case).
</security>
