<objective>
Close hand-driven gap H-3a from `05-UAT.md` (Wave 1 re-verify): plan 05-19
correctly hid child sessions from `sessions list` by default, but did NOT add
the symmetric read-side routing layer. Result: in js-debug pwa-node (and
pwa-chrome), every thread-scoped command (`stack`, `scopes`, `variables`,
`evaluate`, `continue`, `pause`, `next`, `step-in`, `step-out`) against the
parent name now fails with `controller_unavailable: No child session owns
thread N.` because the router requires `threads` to have been called first to
populate a parent-visible thread-id remap. Pre-19 behavior worked (thread 1
on parent returned a 15-frame stack); post-19 it does not. This plan restores
that and goes further: real thread ids end-to-end, `sessionName` annotation
on `threads` aggregation, structured `thread_id_required` error when the user
omits `--thread-id` against a parent with children, and live child lookup so
late-spawned workers route correctly.

Purpose: Hand-driven users only ever see the parent name — children are
hidden by 05-19 by design. Every command that takes a `--thread-id` MUST
just work against the parent. The user MUST NOT have to know about child
topology, type 32-hex child names, or call `threads` first to populate any
internal remap state.

Output: `ChildSessionCoordinator` routes thread-scoped commands by real
child thread ids; `aggregateThreads` adds `sessionName`; `thread_id_required`
error code lists available threads across children; `goto` and `setVariable`
added to the routable set; tests assert parent-name routing works for the
full thread-scoped command surface.
</objective>
