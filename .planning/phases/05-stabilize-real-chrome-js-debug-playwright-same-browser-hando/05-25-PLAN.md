<objective>
Close hand-driven gaps **H-1a** and **H-1b** from `05-UAT.md` `## Hand-Driven CLI Smoke (Wave 1 closure re-verify)`. Both gaps share one root cause: in js-debug pwa-node (and pwa-chrome) the `stopped`/`continued` events arrive on the CHILD runtime, but plan 05-17 only wired `manager.updatePausedState` into the PARENT runtime's `client.onEvent` handler. The parent record never observes a paused state, so:

- **H-1a:** `projectSessionStatus(parent)` correctly omits `paused`/`stoppedReason`/`stoppedThreadIds` (they are `undefined` on the record), making the keys absent from the `status` JSON envelope.
- **H-1b:** `updatePausedState` is never invoked for the parent. Child sessions are hidden by default (plan 05-19) and the user has no other handle, so paused state is invisible end-to-end.

Diagnosis evidence:
- `src/controller/server.ts:347-355` — `client.onEvent` on the **parent** DAP client fires `void manager.updatePausedState(session.id, …)`. In pwa-node, this client is the wrapper; the runtime that emits `stopped` is the child.
- `src/controller/childSessions.ts:handleStartDebugging` registers two child listeners (`initialized` watcher + `mirrorChildEvent`) but neither calls `updatePausedState`.
- `mirrorChildEvent` only annotates the event with `child_session_id` and appends to the parent's event cache.
- Per `/memories/repo/dap-cli.md`: in pwa-node, threads + stopped events live on the child session. Confirmed by Sequence A Step 5 (stack via the child returned a 15-frame stack at `dapCliSelfHostDemo` line 2:18 while parent.paused was null).

**Design decision: parent-mirror, NOT walk-children-at-status-time.** Rationale:
1. Parent is the user-facing aggregate (children are hidden by default per 05-19). The user types `status --name smoke-node`, not `status --name smoke-node#abc…`.
2. Mirroring on event arrival = single write, no extra reads on every `status` call. Walk-at-read would also race with `manager.target()` resolution.
3. The persistence model already exists from 05-17. We only need to invoke it from the right place.
4. Semantics: parent's `paused: true` ≡ "at least one child of this parent is currently stopped". Last-event-wins is acceptable — pwa-node has a single primary debuggee child, and pwa-chrome users observing multi-target stops still see the most recent transition (the right behavior for hand-driven debugging).

**Output:** `dap-cli status --name <parent>` reports paused-state correctly for js-debug pwa-node and pwa-chrome, closing the hand-driven feedback loop.
</objective>
