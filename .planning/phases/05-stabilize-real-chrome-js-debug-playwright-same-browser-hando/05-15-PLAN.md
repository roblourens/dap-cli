<objective>
Close the handoff-smoke half of gap #11 by routing `setBreakpoints` to the
**parent** js-debug session (not fanning it out to children). The direct DAP
trace spike (recorded in `deferred-items.md` as "Definitive triage from direct
js-debug DAP trace (post 05-14)") proves js-debug pwa-chrome's contract is:
parent owns the provisional bp registry and propagates internally to children.
Sending `setBreakpoints` to a pwa-chrome child returns `{breakpoints: []}` —
that's not a bug we can fix on the child side; we have to stop calling that
API on children.

Purpose: Make `npm run test:smoke:handoff` green end-to-end with the strict
assertions from plan 05-05, without weakening any existing tests or losing
the legitimate fan-out behavior for adapters that need it.

Output: Updated `ChildSessionCoordinator.maybeIntercept` + `runChildLifecycle`
in `src/controller/childSessions.ts`, updated unit tests in
`tests/controller/sessionManager.test.ts`, and a green strict handoff smoke.
</objective>

    - When `adapterId === 'js-debug'` and `command === 'setBreakpoints'`, `maybeIntercept` calls `parentClient.request('setBreakpoints', args)` exactly once and does NOT iterate `this.children`.
