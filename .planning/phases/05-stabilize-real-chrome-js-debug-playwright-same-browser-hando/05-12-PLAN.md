<objective>
Close UAT gap 13 (minor — `events --limit 500` silently returns 100; orphaned controllers from prior days served new CLI requests).

Purpose: The event cache has a hardcoded `defaultEventCacheCapacity = 100` with no override path; `--limit > capacity` is silently clipped. Separately, `start` returns `started: false` when a controller socket exists but performs no version/build handshake, so a controller built yesterday silently serves today's CLI.

Output: `events` response includes `truncatedToCapacity` when the requested limit exceeded the cache capacity; controller exposes a build identifier (e.g. `dist/index.js` mtime + size hash) and refuses reuse on mismatch with an actionable error; explicit `stop-controller` command shipped.
</objective>

    1. Generate a deterministic build identifier in a new file `src/controller/buildId.ts`:
       - Read `package.json`'s `version` field once (use a static `import pkg from '../../package.json' assert { type: 'json' }` if tsconfig allows, otherwise read+parse via `fs.promises.readFile` at startup and cache).
       - Try to `fs.promises.stat('dist/index.js')` (path resolved relative to the controller entrypoint, NOT cwd). On success: `BUILD_ID = \`${pkg.version}:dist:${stat.mtimeMs}:${stat.size}\`` — deterministic across CLI and controller processes built from the same dist.
       - On stat failure (running from source via `tsx`/vitest — the normal dev case): fall back to `BUILD_ID = \`${pkg.version}:src\`` — deterministic across the CLI process and the controller process within the same source-tree checkout. **Do NOT include `process.pid` or `Date.now()`** — those make every dev process unique, which would trip "stale controller" rejection on every controller reuse during `npm test` / interactive dev (the opposite of the gap's intent).
       - Tradeoff to document in the SUMMARY: the source-mode id only changes when `package.json` version changes, NOT when source files change. That's acceptable because (a) in dev you typically reload the controller manually after meaningful refactors anyway, and (b) the alternative (content hash of every loaded source file) is expensive at startup and brittle to partial recompiles. If finer granularity is needed later, upgrade to a sha1 of resolved entrypoint contents — but ship the simple version now.
    2. In `startControllerServer`, capture `BUILD_ID` at startup and include it in the `controller.status` IPC response and a new `controller.hello` IPC response.
    3. In `startControllerProcess` (search for it; lives in `src/cli/commands/controller.ts` based on the controller import chain — verify), before reusing an existing socket, send a `controller.hello` request, compare the returned `buildId` to the current process's computed `BUILD_ID`. On mismatch:
       - Return a `started: false, reused: false, mismatch: { existingBuildId, currentBuildId }` envelope with an actionable diagnostic instructing the user to run `dap-cli stop-controller` and retry. Do NOT auto-shut-down — that's destructive.
       - On match: return `started: false, reused: true` (existing behavior).
    4. Add `dap-cli stop-controller` command in `src/cli/commands/controller.ts`:
       ```
       program.command('stop-controller')
         .description('Shut down the persistent controller (does not affect on-disk session records)')
         .action(async () => {
           const client = await createControllerClient({ dapCliHome: process.env.DAP_CLI_HOME });
           try { await client.request('controller.shutdown'); } finally { await client.close(); }
           writeJsonSuccess({ stopped: true }, { command: 'stop-controller' }, stdout);
         });
       ```
    5. Tests in `tests/controller/controllerIpc.test.ts`:
       - "controller.hello returns the build id" — start an in-process controller, call hello, assert buildId is a non-empty string.
       - "stop-controller IPC shuts down the controller" — start, call shutdown via the client.shutdown handler (or via the new CLI command), assert subsequent connect attempts fail.
       - "build-id mismatch is surfaced by the start path" — simulate by running `startControllerProcess` once, then mutating the in-memory expected build-id, then calling start again; assert the returned envelope contains `mismatch`.
       - For the test that uses real CLI (`runCli(['stop-controller'])`), use `createCliTestEnv`.
    6. **Do not break `tests/helpers/runCli.ts > stopController` cleanup path** — it sends `controller.shutdown` directly. Confirm it still works.
