<objective>
Close UAT gaps 6 (recovery-hint diagnostic uses unrunnable syntax) and 9 (`cleanup` does not remove session records). Both share the same edit surface (`sessions.ts` CLI + sessionManager + the diagnostic string in server.ts) so they're grouped together to keep file ownership clean.

Purpose: The `adapter_transport_closed` diagnostic currently says ``Run `dap-cli close <id>` and relaunch the session.`` but `close` rejects positional args (`error: too many arguments for 'close'`). And `cleanup` claims `cleaned: [<sessionId>]` but the same session still appears in `dap-cli sessions` afterward — it only signals SIGTERM and never mutates `data.sessions`. Result: stale records accumulate forever and every subsequent status/threads call hits `adapter_transport_closed`.

Output: `close` accepts an optional positional id; `cleanup` removes records after SIGTERM and supports `--force`/`--purge` for stuck sessions; meta-test grep-extracts every `dap-cli ...` suggestion from emitted diagnostics and asserts each parses through commander.
</objective>

  <action>
    1. In `SessionManager.cleanupSessions`, change the signature to `cleanupSessions(options?: { purge?: boolean }): Promise<CleanupResult>`. After successfully signalling SIGTERM (or treating ESRCH as already-dead), remove the session record from `data.sessions` and persist via `this.persist()`. Keep the `cleaned` array tracking which sessionIds were removed.
       - When `options.purge === true`: also remove records for sessions whose `ownedAdapter.startedByDapCli !== true` OR `pid === undefined` (i.e. records the manager doesn't actively own — the cases where SIGTERM cannot be sent). Add their IDs to `cleaned`.
       - On signal failure other than ESRCH, leave the record in place and add to `failed` (existing behavior). Do NOT remove records that errored.
       - If activeSessionId points to a removed session, clear it.
       - Persist exactly once at the end (not per session) — collect removals, then `this.data = {...}` once, then `await this.persist()`.
    2. In `src/cli/commands/sessions.ts`, change the `cleanup` command:
       ```
       .command('cleanup')
       .option('--force', 'alias for --purge (legacy)')
       .option('--purge', 'also remove records for sessions dap-cli does not own')
       .action(async (options: { force?: boolean; purge?: boolean }) => {
         const purge = options.purge === true || options.force === true;
         await withController(stdout, 'cleanup', client => client.request('sessions.cleanup', { purge }));
       });
       ```
    3. In the controller server's `sessions.cleanup` handler (search for it in `src/controller/server.ts`), thread the `purge` arg through to `manager.cleanupSessions({ purge })`.

       - "cleanup --purge removes stale records the manager does not own" — directly seed `sessions.json` with a record whose `ownedAdapter.startedByDapCli === false`, run `cleanup --purge`, assert removed.
       - "cleanup without --purge leaves records the manager doesn't own" — same seed, run `cleanup` (no flag), assert record remains.
