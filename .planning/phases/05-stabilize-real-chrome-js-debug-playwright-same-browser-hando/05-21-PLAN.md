<objective>
Close hand-driven gap H-5 from `05-UAT.md`: all adapter log files in
`~/.dap-cli/logs/` are 0 bytes. Adapter stdout/stderr capture appears broken
— it isn't, but the result is the same: when something goes wrong the user
opens the log path mentioned in the diagnostic and finds nothing useful.

Purpose: Make the log path in error diagnostics actually useful. Two-part fix:
(1) write a dap-cli header line on adapter startup so 0-byte logs are
unambiguous; (2) for js-debug, enable its built-in trace logging so the log
captures the DAP traffic that's currently invisible because js-debug uses its
socket transport rather than stderr.

Output: Non-empty log files for all adapter launches; js-debug logs include
DAP trace.
</objective>
