<objective>
Close UAT gap 11 (blocker — `npm run test:smoke:handoff` fails because `fanOutSetBreakpoints` swallows per-child errors with `try/catch returning undefined` and returns `{ breakpoints: [] }` whenever every child failed; additionally a child can be in `threads` before its `configurationDone` completes, so the test's poll-until-non-empty-threads gate can race the readiness window).

Purpose: Surface child errors instead of silently dropping them; gate `setBreakpoints` (and any other fan-out commands) on child readiness so the strict handoff smoke can't race; then run `npm run test:smoke:handoff` end-to-end and capture the green output.

Output: `fanOutSetBreakpoints` returns `{ breakpoints, warnings? }` with per-child errors when present; `awaitChildrenReady()` is a public method on `ChildSessionCoordinator`; the handoff smoke test provisions js-debug into its tmp env (using the helper added in plan 05-08), waits for readiness before setting breakpoints, and asserts every strict criterion.
</objective>

<task type="auto">
  <name>Task 1: Track child readiness; surface fan-out errors</name>
  <files>src/controller/childSessions.ts</files>
  <action>
    1. Extend `ChildRuntime` with a new `readyPromise: Promise<void>` and `readySeen: boolean` field. Resolve `readyPromise` at the end of `runChildLifecycle` after `await this.options.sessionManager.updateLifecycle(childId, 'running')`. On failure path (`markChildFailed`), reject `readyPromise` with the underlying error so callers awaiting it see why the child never became ready. Capture the resolver/rejecter the same way `initializedPromise` does.
    2. Add a public method `public async awaitChildrenReady(): Promise<void>` that does `await this.awaitPendingChildren()` then `await Promise.allSettled([...this.children.values()].map(c => c.readyPromise))`. This is intentionally `allSettled` — it's "wait for them to settle one way or the other," not "fail if any failed."
    3. Modify `fanOutSetBreakpoints(args)`:
       - First call `await this.awaitChildrenReady()` so children that are still mid-handshake have a chance to finish.
       - Replace the existing `try { ... } catch { return undefined; }` with `try { ... } catch (error) { return { error }; }`. Type the per-child result accordingly.
       - Aggregate: build the `breakpoints` array as today (taking the first non-undefined `breakpoints` field, OR-merging the `verified` flag across children).
       - If any per-child result has `.error`, attach a `warnings: Array<{ sessionId: string; message: string }>` field to the returned response. Use the child runtime's `sessionId` for identification. Include the warnings even when some children succeeded.
       - When `responses.length > 0` and **every** response is an error, do NOT return `{ breakpoints: [] }` silently — return `{ breakpoints: [], warnings: [...] }` so the upstream caller can see what went wrong. (The shape stays compatible with DAP `SetBreakpointsResponse` because `warnings` is an additional field.)
    4. Add JSDoc on `awaitChildrenReady` and `fanOutSetBreakpoints` describing the new contract.
    5. Add a unit test in `tests/controller/sessionManager.test.ts` (or a new `tests/controller/childSessions.test.ts` if cleaner — look at how other coordinator tests are structured) that constructs a `ChildSessionCoordinator` with a fake parent client whose reverse-request handler simulates two children. Mock the child clients so one resolves `setBreakpoints` and the other rejects with `Error('boom')`. Assert the aggregated response has `breakpoints.length >= 1` AND `warnings` contains one entry mentioning `boom` and the failed child's sessionId.
       - If wiring up two synthetic children directly is too heavy, instead test `fanOutSetBreakpoints` through a smaller seam: split the per-child request loop into a private helper that takes `Array<{ sessionId; client }>` and assert that helper directly. Either is acceptable; the goal is deterministic coverage of the new error-surfacing path.
