Close the chrome-smoke half of gap #11. The trace spike (recorded in
`deferred-items.md` under "Definitive triage from direct js-debug DAP trace
(post 05-14)") proves the chrome-smoke times out because the raw single-
process `DapClient` in `runJsDebugBreakpointSmoke` does NOT handle the
`startDebugging` reverse request js-debug emits after `configurationDone`.
Without that handler, no page child is ever connected, the parent's
provisional breakpoint never propagates, and `stopped` never fires.

Purpose: Install a `startDebugging` reverse-request handler in
`runJsDebugBreakpointSmoke` so the chrome-smoke test can drive the same
nested-session flow that the controller already handles via plan 05-14's
`ChildSessionCoordinator.installStartDebuggingHandler`. This is Option A
from the recommended split — preferred over migrating the chrome-smoke to
run through the controller because it keeps the test path narrow and
avoids coupling the smoke to any controller behavior.

Output: An updated `runJsDebugBreakpointSmoke` helper in
`tests/integration/jsDebugAdapter.test.ts` and a green chrome-smoke under
`DAP_CLI_RUN_BROWSER_SMOKES=1`.
