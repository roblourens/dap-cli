<objective>
Close hand-driven gap H-6 — the BLOCKER from `05-UAT.md`. The shipping CLI
cannot drive a pwa-chrome breakpoint to a stopped state, even though
`npm run test:smoke:chrome` and `npm run test:smoke:handoff` are green. The
green test status is misleading because
`tests/integration/jsDebugAdapter.test.ts:runJsDebugBreakpointSmoke` installs
a `startDebugging` reverse-request handler in-test that the production
controller path does not need (it has its own coordinator), but ALSO does
something else the production path is missing — most likely propagating
webRoot/pathMapping into the child configuration.

Per direct DAP trace evidence in `deferred-items.md` and
`/memories/repo/dap-cli.md`: the parent owns the bp registry; the parent
emits startDebugging after configurationDone; the recursive depth=1 child
handler is already in place from 05-14; setBreakpoints routing to parent is
in place from 05-15. The gap is the LAST mile — whatever is missing from
the published controller path that prevents the provisional bp from
resolving when the page child loads app.js.

Purpose: Make hand-driven Sequence B Step 5 (`stack --name smoke-chrome
--thread-id 1`) return frames in app.js after the page runs `calculate(2,3)`,
verified by `events --include stopped` showing a breakpoint stop within 10s.

Output: Production controller fix (NOT a test-helper fix) + new
controller-driven integration test that would have caught this.
</objective>
