<objective>
Close the chrome-smoke half of UAT gap #11. The post-12 diagnostic spike confirmed the chrome-smoke test passes `setBreakpoints` (parent client returns a length-1 placeholder) but never observes a `stopped` event because pwa-chrome never resolves the placeholder against the real `file://.../app.js` script. Root cause: the test's launch config has no `webRoot`, so pwa-chrome can't map the local OS path supplied to `setBreakpoints` onto the parsed `file://` script URL the page actually loads.

Purpose: Make the gated chrome-smoke green so we have a known-good single-process pwa-chrome breakpoint baseline. Without this baseline, plan 05-14's recursive-coordinator work has no oracle for "the breakpoint really resolves once a webRoot is set."

Output: One-line edit to the chrome-smoke launch config in `tests/integration/jsDebugAdapter.test.ts` adding `webRoot: path.dirname(page)`, plus a re-run of `npm run test:smoke:chrome` showing the test now passes end-to-end.
</objective>
