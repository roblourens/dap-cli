<objective>
Close hand-driven gap H-3 from `05-UAT.md`: child sessions
(`smoke-node#<hex>`, `smoke-chrome#<hex>`) appear in `sessions list` with
`lifecycle: running` but every command against them returns
`session_unavailable: No DAP runtime is attached`. This is a UX/contract bug:
either expose them properly or hide them. Per `/memories/repo/dap-cli.md`
(verified by direct DAP trace), the parent owns the breakpoint registry and
threads in js-debug pwa-chrome, so children should NOT be targeted directly.
The right fix is: hide by default + return a clear, actionable error instead
of `session_unavailable` when someone targets one.

Purpose: Make `sessions list` honest (only show targetable sessions by
default) and make targeting failures self-diagnosing instead of pointing the
user at `cleanup` for what is actually a contract issue.

Output: `sessions list` filters children by default, `--show-children` opt-in,
new `child_session_not_targetable` error code with proper diagnostic.
</objective>
