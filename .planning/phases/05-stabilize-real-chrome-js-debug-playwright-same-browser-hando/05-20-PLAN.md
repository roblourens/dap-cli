<objective>
Close hand-driven gaps H-4 (cleanup is dishonest about what it did) and H-7
(`controller_unavailable: Run dap-cli start` is the wrong recovery hint when
the real problem is "thread not paused") together. Both are diagnostic-message
audits — they share the surface area in `controller/diagnostics.ts`,
`sessionManager.ts`, and the error contract tests.

Purpose: Make hand-driven recovery hints accurate. Right now the user is told
to run `dap-cli cleanup` (which silently no-ops) when they should run
`cleanup --purge`, and they are told to run `dap-cli start` (which is already
running) when the actual issue is "the thread isn't paused — poll events for
a stop event first."

Output: Honest `cleanup` response shape with `keptRunning` reasons; new
`thread_not_paused` error code; codebase-wide diagnostic-message audit
replacing `cleanup` with `cleanup --purge` where appropriate.
</objective>
