<objective>
Close the handoff-smoke half of UAT gap #11. The post-12 diagnostic spike confirmed the controller-coordinated handoff path returns `{breakpoints: []}` from the single observed child — a DAP spec violation strongly indicating that "child" is actually an intermediate pwa-chrome wrapper, not the page-level grandchild that owns the parsed script. `ChildSessionCoordinator.attach()` only installs `onReverseRequest` on the **parent** client today, so nested `startDebugging` requests issued by the wrapper child are never observed and the page-level grandchild is never brought up as a tracked session.

Purpose: Extend the coordinator so the same `startDebugging` reverse-request handler is installed on every client it brings up — parent and every child — so deeply-nested pwa-chrome session trees flatten into a single layer of real child sessions under the parent. After this lands, `fanOutSetBreakpoints` (already gated on per-child readiness from plan 05-09) reaches the page-level session and gets a real, non-empty response.

Output:
- `src/controller/childSessions.ts`: `startDebugging` handler installation factored out and applied to every child client during bring-up; child registration via nested startDebugging routes the same `parentSessionId`/`parentEventCache`/`parentName` so grandchildren appear flat under the original parent.
- `tests/controller/sessionManager.test.ts`: unit test asserting grandchild registration via nested startDebugging.
- `tests/integration/playwrightInterop.test.ts`: strict handoff smoke now passes end-to-end (no test logic change beyond what 05-09 already shipped — the assertion gate is what changes once the page-level child is observable).
</objective>

  <name>Task 1: Install `startDebugging` handler on every child client (recursive coordination)</name>
  <files>src/controller/childSessions.ts</files>
  <action>
    1. Read the existing `attach()` method. Today it captures the chained-promise scheduling logic in a closure and registers `onReverseRequest` on `this.options.parentClient` only. The same handler logic must be installable on any `DapClient` we bring up.
    2. Refactor: extract the startDebugging dispatch closure into a private method, e.g.:
       ```typescript
       private installStartDebuggingHandler(client: DapClient): () => void
       ```
       It should:
       - Maintain the same per-client serialization invariant the current `attach()` uses (`chain = chain.then(...)`) so registration order in `this.children` stays deterministic per source client.
       - Track the returned dispose function so `dispose()` can detach handlers from every client (parent and all children).
       - Push the dispatch promise into `this.activeHandlers` exactly like today, so `awaitPendingChildren()` still observes them.
    3. Update `attach()` to call `this.installStartDebuggingHandler(this.options.parentClient)` and store the dispose function the same way `detachReverseHandler` stores the parent's today (replace the single field with a small `Set<() => void>` of detach functions; iterate it in `dispose()`).
    4. In the existing child bring-up flow (inside `handleStartDebugging`, AFTER `client = factory(transport)` and BEFORE `await client.request('initialize', ...)`), call `this.installStartDebuggingHandler(client)` so the new child's reverse-request handler is wired immediately. This is the entire behavioral change — nested startDebugging from this child will now be handled by the same coordinator, registering the grandchild under the same `parentSessionId` (because all the registration code already uses `this.options.parentSessionId`/`parentEventCache`/`parentName`, no per-child threading is needed).
    5. Sanity audit:
       - `dispose()` must detach the handler from every child client too. With the `Set<() => void>` approach above, iterate and call each. Order doesn't matter; existing `await` ordering is preserved.
       - `runChildLifecycle` does NOT need any change — the existing replay-of-initial-breakpoints-on-future-children loop already runs against `this.children.values()`, so it naturally covers grandchildren too.
       - `aggregateThreads()`, `routeBy*()` already iterate `this.children.values()`. Grandchildren are flat siblings under the same parent, so existing routing works without modification.
    6. Add JSDoc on `installStartDebuggingHandler` explaining: "Installed on parent AND on every child as it's brought up. pwa-chrome's session model nests browser-level → page-level — without this, grandchild page sessions are never observed by the controller and `setBreakpoints` fan-out misses the session that actually owns the parsed scripts."
    7. Run `npx tsc --noEmit`. Must be clean.
  </action>
