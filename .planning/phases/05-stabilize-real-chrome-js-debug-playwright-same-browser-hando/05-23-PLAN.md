<task type="auto" tdd="true">
  <name>Task 1: terminateDebuggee on disconnect + centralized terminateRuntime helper</name>
  <files>src/protocol/lifecycle.ts, src/controller/server.ts, tests/controller/sessionManager.test.ts</files>
  <behavior>
    - `DapLifecycleController.disconnect(opts?: { terminateDebuggee?: boolean })` accepts the option and forwards it as the DAP `disconnect` request body. Default behavior unchanged when called with no args.
    - New private method on `ControllerServer`: `terminateRuntime(runtime: DapSessionRuntime, opts: { terminateDebuggee: boolean }): Promise<{ orphanPids: number[]; warnings: string[] }>`. Steps:
      1. If `runtime.children` exists, dispose it (existing).
      2. `await runtime.lifecycle.disconnect({ terminateDebuggee: opts.terminateDebuggee }).catch(() => undefined)`.
      3. Wait up to 5s for runtime.adapter.close() to complete OR the owned-adapter PID to exit (whichever first).
      4. After the wait, probe liveness of the owned-adapter PID via `process.kill(pid, 0)` (returns true if alive). If still alive, send SIGTERM, wait 200ms, send SIGKILL if still alive, wait 200ms again.
      5. Collect surviving PIDs (just the adapter PID for now — child-process-tree walking is best-effort and noted in the SUMMARY as a follow-up if not trivially derivable from the existing process info).
      6. Return `{ orphanPids: <surviving PIDs>, warnings: orphanPids.length > 0 ? ['orphan_processes_remain: ' + orphanPids.join(', ')] : [] }`.
    - `ControllerServer.handleSessionRequest('sessions.close')` calls `terminateRuntime(runtime, { terminateDebuggee: true })` BEFORE `manager.closeSession(target)`. The result is merged into the response: `{ ...sessionStatus, orphanPids, warnings }`.
    - `ControllerServer.handleSessionRequest('sessions.cleanup')` with `purge: true` ALSO calls `terminateRuntime` for each runtime being torn down.
    - `ControllerServer.stop()` replaces its inline `runtime.lifecycle.disconnect/runtime.client.close/runtime.adapter.close` chain with a `terminateRuntime(runtime, { terminateDebuggee: true })` call per runtime — converges behavior.
    - Unit tests: (a) close on a fakeAdapter session sends DAP disconnect with terminateDebuggee:true (use the fake adapter's request log); (b) when the signal helper is mocked to keep returning alive, terminateRuntime returns orphanPids with the mock PID.
  </behavior>
  <action>Implement per behavior block. The signal helper is already swappable via `SessionManager.options.signalProcess` — use the same indirection in terminateRuntime so tests can mock kill semantics. Do NOT walk `/proc` or shell out to `pgrep` for child-process discovery in this plan; that's a follow-up if the basic SIGKILL doesn't reach Chromium subprocesses (which it likely will, since js-debug spawns them as children of its own PID and SIGKILL'ing js-debug should cascade in most cases — verify in Task 2's hand-driven check).</action>
