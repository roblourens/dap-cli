<objective>
Make `dap-cli status` reflect the most recent `stopped` / `continued` event so polling loops have a single source of truth. Today, parent js-debug (pwa-node / pwa-chrome) sessions whose `stopped` events arrive on a child runtime mirror `paused: true` onto the parent record but do NOT update parent `lifecycle`, so `status` keeps reporting `'running'` even though `events --limit 200` clearly shows `{event: stopped, reason: breakpoint}`. The fix is a one-line change in `projectStatusState` plus tests and a docs cleanup.

Purpose: Closes the first half of `analysis.md`'s paused-state ergonomics complaint. The mirror is already in place (plans 05-17 / 05-25); only the projection ignores it.
Output: Updated projection in `src/sessions/session.ts`, new test cases proving `SessionStatus.status` flips with `updatePausedState`, and a docs sweep removing the "poll events for stop detection" misguidance.
</objective>

```typescript
client.onEvent(event => {
  if (event.event === 'stopped') {
    void this.options.sessionManager
      .updatePausedState(this.options.parentSessionId, derivePausedStateFromStopped(event.body))
      .catch(() => undefined);
```
