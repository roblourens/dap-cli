<objective>
Make `dap-cli evaluate` work without manual `threads → stack → grab frameId → evaluate` plumbing whenever the session is paused. When `--frame-id` is omitted AND the session is paused, the CLI auto-resolves the topmost frame of the most-recently-stopped thread before dispatching the DAP `evaluate` request. Explicit `--frame-id` still wins; not-paused sessions are unchanged.

Purpose: Closes the second half of `analysis.md`'s paused-state ergonomics complaint. Today every inspect requires a four-command sequence; after this plan the canonical inspect is one command.
Output: A small handler change in `src/cli/commands/dapAliases.ts`, integration coverage exercising every matrix cell via the fake adapter, and a docs sweep showing the new short form.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user shell → dap-cli CLI | `--expression` is user-controlled, passed to the adapter unchanged (existing trust model — the adapter is the policy boundary for evaluation). |
| dap-cli CLI → controller | Auxiliary `sessions.status`, `dap.request threads`, `dap.request stackTrace` calls cross the existing IPC boundary; no new wire shape. |
| adapter → CLI | `threads` / `stackTrace` response bodies are untrusted; this plan reads `threads[0].id` and `stackFrames[0].id`. Coerce to integer before use. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-02-01 | Tampering | adapter `threads` / `stackTrace` response bodies feeding `frameId` resolution | mitigate | In `resolveAutoFrameId`, validate `threads[0].id` and `stackFrames[0].id` are `Number.isInteger(...)` before using them; on failure, fall through to B-fallback (no frame, with stderr hint). Same coercion discipline as `derivePausedStateFromStopped` (plan 05-17). |
| T-11-02-02 | Information Disclosure | stderr hint echoes `threadId` from adapter | accept | The `threadId` is already part of the adapter's own response; echoing it back to the user is not disclosure. |
| T-11-02-03 | Denial of Service | repeated `evaluate` calls each trigger an extra `sessions.status` + `threads` + `stackTrace` round-trip | accept | Cost is bounded (3 extra IPC calls per `evaluate`). The agent workflow is already polling-driven; adding 3 calls per inspection is well under the existing event-cache poll budget. Future optimization (cache the last paused state in the controller) is out of scope. |
| T-11-02-04 | Tampering | malicious adapter returns a `frameId` for a frame the user did not "select" | accept | The user passed NO `--frame-id`, so any frame the adapter chooses is by definition acceptable — the auto-frame contract is "topmost frame the adapter reports." Same trust model as today's manual `stack → frameId → evaluate` recipe. |
</threat_model>
