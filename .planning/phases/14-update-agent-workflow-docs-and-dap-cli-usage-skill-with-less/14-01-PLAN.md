<objective>
Capture the analysis.md lessons in the agent-facing documentation surface (in-repo `docs/AGENT-WORKFLOWS.md`, `README.md`, and the user-level `~/.copilot/skills/dap-cli/` skill). Phases 10–13 shipped the underlying CLI behavior; Phase 14 makes sure agents reading the docs/skill actually find that behavior and stop hitting the original footguns.

Purpose: An agent following the skill or AGENT-WORKFLOWS.md from a cold start should:
1. Pick the right verb (or trust `--config` auto-route) for an attach-shaped launch.json config.
2. Prove they hit the right process before anything else.
3. Read `verificationDiagnostic` instead of guessing source-map config when a breakpoint won't bind.
4. Poll only `status` for stop detection.
5. Know that child sessions are not targetable.
6. Stop threading `--no-human` through every command.
7. Default to the auto-frame `evaluate` short form.

Output: Four updated markdown files (two in-repo, two in `~/.copilot/skills/dap-cli/`) plus a green `docsValidation.test.ts`.
</objective>

From Phase 13 resolver semantics (canonical reference for any output-mode wording):
- Piped/redirected stdout → JSON regardless of `DAP_CLI_HUMAN`.
- TTY + `DAP_CLI_HUMAN=1` → human.
- Explicit `--human` / `--no-human` always win.
- Therefore: `--no-human` is no longer required in agent pipelines and should be removed from default examples; mention it only as the explicit-override escape hatch.

From Phase 10 auto-route:
- `--config <name>` inspects the resolved launch.json `request:` field; if it differs from the CLI verb, the controller dispatches the matching DAP request and emits a `warnings` entry plus `autoRouted: { from, to }` on the success payload.
- Raw `--json` and CLI-flag-only invocations are NOT auto-routed; the verb wins. The wrong-process smoke recipe still matters there.

From Phase 11 status semantics:
- `status` reflects the most recent `stopped`/`continued` event for both single-process adapters and js-debug parent sessions (parent mirrors child stops via `paused`).
- `evaluate` auto-resolves `--frame-id` to the topmost paused frame on a paused session when omitted.

From Phase 12 verificationDiagnostic:
- On any unverified breakpoint, success payload gets a `verificationDiagnostic` with `hint`, `recipe` (literal `dap-cli dap loaded-sources [--name <session>]`), and `matchingLoadedSources`.
- The `wrong process` substring exists specifically for grep.

From SKILL.md frontmatter shape (~/.copilot/skills/dap-cli/SKILL.md):
- YAML frontmatter with `name`, `description`, `argument-hint`. Preserve exactly. Body is markdown; sections currently include Goal, When To Use, Core Model, Standard Loop, Common Commands, Breakpoint Workflow, launch.json Workflow, Failure Handling, More Detail.
