<objective>
Add `--json-overrides <json>` and `--resolve-source-maps <pattern...>` flags to `dap-cli launch` and `dap-cli attach` so users can layer extra fields onto a `--config`-resolved configuration without abandoning `--config` entirely.

Purpose: Per `analysis.md` item 9 and CONTEXT.md item 2/3, today the only escape hatch for adding fields to a named launch.json config is to drop `--config` entirely and rebuild via `--json`. Real-world repos (the vscode repo's "Attach to Agent Host Process" config sets only `outFiles`; js-debug also wants `resolveSourceMapLocations` and explicit `sourceMaps:true` to bind compiled-JS breakpoints). Users should be able to layer those on without losing the workspace's launch.json.
Output: Two new flags, a new merge layer in `resolveLaunchConfig`, full unit + integration coverage, and updated docs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user shell → dap-cli CLI | `--json-overrides` is a JSON string from the shell; parsed as untrusted input. |
| `--json-overrides` → resolved config | After parse + record-shape check, the object is treated as adapter config (already a trusted surface for `--json` and `--config`). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-02-01 | Tampering | `--json-overrides '{"request":"launch"}'` to bypass plan 01's auto-route | mitigate | The `request: effectiveMode` literal is the LAST write in the config object construction (after the spread). Override values for `request:` are silently overwritten. Asserted by Task 2 unit test #9. |
| T-10-02-02 | Denial of Service | `--json-overrides` with deeply nested object | accept | `parseJsonOption` uses `JSON.parse` which has Node's standard recursion handling; same surface as the existing `--json` flag (no new attack surface). |
| T-10-02-03 | Injection | `--resolve-source-maps` patterns sent to js-debug glob matcher | accept | Glob patterns are interpreted by js-debug; same trust model as the existing `--out-files` flag (workspace-trusted globs). No new sandbox is required. |
| T-10-02-04 | Tampering | Type confusion via non-object JSON (`"string"`, `[]`, `null`) | mitigate | `parseJsonRecordOption` enforces `typeof === 'object' && !Array.isArray && !== null`; non-objects throw `usage_error code:'invalid_json'`. Asserted by Task 2 unit cases #3–5. |
</threat_model>
