<objective>
Add a best-effort diagnostic that catches the original `analysis.md` failure mode even on code paths that bypass plan 01's auto-route. When js-debug spawns a helper process during a `launch` and dap-cli is asked to inspect the helper's PID, the helper's `ppid` matches the dapDebugServer adapter's PID. The detector watches DAP `process` events on js-debug sessions, looks up `systemProcessId`'s parent PID via `ps`, and if it matches the adapter PID, emits a synthetic `dapCli.helperProcessWarning` event.

Purpose: Per CONTEXT.md item 4 and `analysis.md` ("when js-debug reports an attach-target PID whose ppid equals the dapDebugServer PID, dap-cli should warn that we likely attached to an adapter-spawned helper process"). This is the diagnostic that would have caught the original bug instantly. Plan 01's auto-route prevents the bug for `--config` users; this warning catches the same bug for `--adapter` / `--json` users who never resolve a named config.
Output: A small, dependency-injected detector module; a wiring point in `server.ts`; unit tests with an injected `lookupPpid`; one integration test; agent-workflow doc update.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dap-cli controller → OS `ps` | Spawning `ps` as a child process; `pid` argument is adapter-supplied. |
| Detector → event cache | Synthetic event injection on the same surface DAP events use. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03-01 | Injection | `pid` argument to `ps` | mitigate | `String(pid)` after `Number.isInteger(pid) && pid > 0` validation. `execFile` (not `exec`) means no shell interpolation. Argv-style invocation. |
| T-10-03-02 | Denial of Service | `ps` hanging | mitigate | Hard 1-second `timeout` on `execFile`; on timeout, treat as `undefined`. Detector never blocks on the lookup (it is async, results processed when ready). |
| T-10-03-03 | Tampering | Adapter sends `systemProcessId: <attacker-chosen pid>` to falsely trigger or suppress the warning | accept | An adapter the user chose to run already controls the debug session; misleading the user about helper-process status is bounded by what the adapter could already do (lie about `process` events entirely). The warning is advisory, not security-critical. |
| T-10-03-04 | Information Disclosure | `dapCli.helperProcessWarning` body includes adapter and helper PIDs | accept | PIDs are local-process metadata that the user already has access to; not sensitive. Documented in the body shape contract. |
| T-10-03-05 | Spoofing | Synthetic event with `seq: -1` could collide with a real DAP event using a negative seq | mitigate | DAP spec guarantees positive sequence numbers from adapters. `seq: -1` is unambiguously a dap-cli synthetic. Document in the module's header comment. |
</threat_model>
