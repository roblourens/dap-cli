<objective>
Drive the 20 scenarios from `17-SCENARIOS.md` to completion, one fresh subagent per scenario, recording each subagent's structured report into `17-RESULTS.md` before moving to the next. Then synthesize findings into `17-UAT.md` with a clear recommended next step.

This plan deliberately uses one subagent per scenario (not one subagent for all 20) so:
- Each scenario starts with a clean context window — no bleed from prior scenarios.
- Agent confusion that's specific to a scenario is observable, not averaged out.
- A single broken scenario cannot derail the rest of the run.

The orchestrator's job is mechanical: pull scenario N's `subagent_prompt`, spawn a subagent with it, capture the structured response, write a row, clean up, advance.
</objective>

## Trust Boundaries

|----------|-------------|
| subagent return text → 17-RESULTS.md | The orchestrator parses subagent text by label; a malicious or confused subagent could attempt to inject content. |
| dap-cli ↔ Code OSS dev build | Real Electron processes spawned with debug ports open on localhost. |
| inter-scenario state | A leaked Code OSS or dap-cli controller process from scenario N corrupts scenario N+1. |

Final sweep at end of Task 2 also stops the global controller. |
