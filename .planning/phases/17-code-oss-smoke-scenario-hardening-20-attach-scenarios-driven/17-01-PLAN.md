| Boundary | Description |
|----------|-------------|
| dap-cli ↔ Code OSS dev build | Real Electron processes are spawned with elevated debugging ports open on localhost. |
| filesystem ↔ scenario matrix | Subagents will execute commands copy-pasted out of the matrix. Untrusted content in the matrix would become an injection vector at execution time. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01-01 | T | scenario matrix as command source | mitigate | The matrix is authored entirely by the executor in this plan from in-repo docs and skill files. No external content (web pages, third-party READMEs) is pasted into `dap_cli_commands` or `subagent_prompt` blocks. |
| T-17-01-02 | I | --remote-debugging-port exposure | accept | All ports bind to localhost only and the dev machine is single-user. Each scenario picks a distinct port to avoid cross-scenario interference. |
| T-17-01-03 | D | orphaned Code OSS processes after a scenario crashes | mitigate | Every scenario's `cleanup` field includes `pkill -f 'scripts/code.sh'` and `dap-cli stop` so the next scenario starts clean. |
</threat_model>
