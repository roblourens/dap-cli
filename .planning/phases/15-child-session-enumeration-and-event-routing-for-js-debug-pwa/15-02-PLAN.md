<objective>
Close CHILD-ERR-01: prove (and fix if necessary) that
`dap-cli events --name <child_session_id>` returns the structured
`child_session_not_targetable` error — the same error class the rest of the
public CLI surface already returns when targeting a child — instead of the
misleading empty `total: 0` that analysis2.md observed.

Code audit (per CONTEXT.md) shows `recentEvents` already calls
`resolveRuntime(name)` which calls `assertNotChildSession` BEFORE returning,
so the structured error MAY already fire today. This plan settles it with a
regression test. If the test passes immediately, the plan ships only the
regression guard (still valuable — the analysis2 evidence implied a real
gap, so we lock the current behavior). If the test fails, the plan also
ships the controller fix that routes the events path through the same gate.

Purpose: kill the analysis2.md confusion that `events --name <child>` looks
like "no events ever" when the real meaning is "you targeted the wrong
session — query the parent". This makes the doc plan (15-03) honest.

Output: a regression test (and any required server-side fix).
</objective>
