<objective>
Close CHILD-VERIFY-01: prove (and fix if necessary) that `console`-category
`output` events from a verified renderer logpoint reach the parent's event
stream tagged with the renderer's `child_session_id`, when debugging a real
pwa-chrome target with `dap-cli`.

Per CONTEXT.md, `ChildSessionCoordinator.mirrorChildEvent` already appends
every child event to the parent's DapEventCache annotated with
`child_session_id`. The analysis2.md §2 symptom (no renderer output observable
on the parent stream) means one of: (a) the mirror is silently dropping
`output` events, (b) the breakpoint was applied to the wrong child
(extension-host vs renderer) so it never fired, or (c) the renderer's child
client never had `onEvent` wired before the logpoint hit. This plan settles
which one, ships the fix, and locks the behavior with a regression test.

Purpose: make the canonical pwa-chrome workflow actually produce observable
renderer output on the parent's event stream — the doc plan (15-03) depends
on this being true.

Output: a focused unit test, any required controller fix, and a captured
hand-driven repro log.
</objective>
