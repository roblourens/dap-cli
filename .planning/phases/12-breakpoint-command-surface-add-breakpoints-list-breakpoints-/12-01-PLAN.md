<objective>
Add the two missing breakpoint subcommands an external agent expected to find next to `breakpoints set`: `breakpoints list` (return all currently-set breakpoints with verified state) and `breakpoints clear` (DAP empty-list semantics, optionally filtered to one source). Closes BPCMD-01 and BPCMD-02 from the analysis.md feedback captured in CONTEXT.md.

Purpose: Today the agent has to track breakpoint state out-of-band or scrape `set` responses, and there's no way to exercise the DAP `setBreakpoints { source, breakpoints: [] }` clear semantics from the CLI surface. Both gaps are obvious counterparts to `breakpoints set`; closing them removes a category of "what command do I run next?" friction documented in `analysis.md` §3.
Output: A small DapSessionRuntime field + setBreakpoints write hook in the controller, two new controller method handlers, two new CLI subcommands wiring straight to those methods, unit + integration coverage of the matrix, and updated docs.
</objective>
