<objective>
Make piped/non-TTY stdout always emit JSON, regardless of `DAP_CLI_HUMAN`. Closes Phase 13 per CONTEXT.md and the analysis.md feedback that drove it: external agents currently thread `--no-human` through every machine-parsed command defensively because an inherited `DAP_CLI_HUMAN=1` would corrupt their JSON parse. Once stdout-is-TTY gates env-derived human mode, the `--no-human` workaround becomes unnecessary.

Purpose: Today `resolveOutputMode` honors `DAP_CLI_HUMAN` whenever `--human` / `--no-human` aren't passed, even when stdout is captured by an agent. The result is fragile pipelines and a SKILL warning that tells agents to defensively pass `--no-human`. Phase 14 (next) drops that warning from the docs; this phase makes the docs change correct.
Output: Resolver gains an `isStdoutTTY` input, both CLI bootstraps wire it from the actual stdout stream, the test helper grows a non-TTY variant, and the resolver + integration matrix asserts the precedence table.
</objective>

export interface ResolveOutputModeInput {
  cliHuman: boolean | undefined;
  env?: NodeJS.ProcessEnv;
}

export function resolveOutputMode(input: ResolveOutputModeInput): OutputMode {
  if (input.cliHuman === true) return 'human';
  if (input.cliHuman === false) return 'json';
  return parseHumanEnv(input.env ?? process.env) ? 'human' : 'json';
}
