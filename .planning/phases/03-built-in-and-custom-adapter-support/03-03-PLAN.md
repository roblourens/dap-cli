Descriptor factory:
```typescript
export function createDebugpyDescriptor(pythonPath?: string): AdapterDescriptor {
  const python = pythonPath ?? resolvePythonPath();
  return {
    id: 'debugpy',
    label: 'Python Debug Adapter (debugpy)',
    transport: {
      kind: 'stdio',
      command: python,
      args: ['-m', 'debugpy.adapter'],
      cwd: undefined,
      env: undefined,
    },
  };
}

function resolvePythonPath(): string {
  // Check common Python executable names in order:
  // 1. python3 (preferred)
  // 2. python
  // Use 'python3' as default - if debugpy not installed, DAP connection will fail with clear error
  return 'python3';
}
```

**Note on debugpy invocation:** debugpy has two modes:
1. **Adapter mode** (used here): `python -m debugpy.adapter` - runs a DAP server that the client sends launch/attach requests to
2. **CLI mode**: `python -m debugpy --listen ... script.py` - directly launches/attaches and waits for client

We use adapter mode because it matches the DAP lifecycle model (initialize → launch/attach → configurationDone). The adapter handles launching Python scripts or attaching to processes based on DAP launch/attach requests.

Update `src/adapters/registry.ts` to include debugpy in built-in adapter map:
```typescript
private readonly builtInAdapters: Record<string, () => AdapterDescriptor> = {
  'js-debug': () => createJsDebugDescriptor(),
  'debugpy': () => createDebugpyDescriptor(),
};
```

Error handling: If Python is not found or debugpy is not installed, the adapter connection will fail at DAP initialize stage. The error will bubble up through existing DAP error handling - no special case needed here.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| debugpy binary → dap-cli process | debugpy runs as subprocess with access to target Python app files and memory |
| Python fixture code → test environment | Test fixtures execute arbitrary Python code during smoke tests |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering | Python interpreter path | mitigate | Use well-known Python executable names (python3, python) from system PATH - do not allow arbitrary paths without validation |
| T-03-11 | Information Disclosure | debugpy logs | accept | debugpy may log sensitive app data during debugging - this is intended behavior. Users control log behavior via debugpy configuration. |
| T-03-12 | Elevation of Privilege | Python execution | accept | Launching Python apps is the core feature - users explicitly provide scripts to debug. Document that dap-cli executes target programs with user privileges. |
| T-03-13 | Denial of Service | debugpy port conflicts | accept | debugpy uses adapter mode which handles port allocation internally - no hardcoded ports in dap-cli |
</threat_model>
