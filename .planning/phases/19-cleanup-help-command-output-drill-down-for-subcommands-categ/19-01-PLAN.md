<objective>
Stop `dap-cli help` and `dap-cli help <path>` from printing a bogus
`(outputHelp)` JSON error envelope (D-01 / HELP-01), and make `dap-cli help`
drill into nested subcommands so `dap-cli help breakpoints set` prints the
help for `breakpoints set` instead of `breakpoints` (D-02 / HELP-02).

Purpose: The current behavior makes the help command unusable as a discovery
tool — the trailing JSON error confuses both humans and agents (looks like
the command failed even though help rendered), and the lack of drill-down
forces users to learn the `<cmd> <subcmd> -h` workaround.

Output: Clean help output (zero envelopes, exit 0) on success, drill-down
that walks the subcommand tree, and a usage_error envelope only when the
requested help path is invalid.
</objective>

  if (!isCommanderError(error)) {

In `src/cli/program.ts`, register a CUSTOM `help` command that walks a variadic command path and prints the deepest match's help. The built-in `help` subcommand is registered automatically by commander — disable it first so the custom one is the only `help` registered.

After all `register*Commands(program, output)` calls and BEFORE the `program.addHelpText('after', ...)` call, add:

```typescript
// Replace commander's default `help [command]` with a variadic walker so
// `dap-cli help breakpoints set` drills into the subcommand tree (per D-02).
// Exit codes: drill-down success returns 0 (help is informational, not a
// failure); unknown path exits 2 with a usage_error envelope written via
// the same writer the failure envelopes use.
program.helpCommand(false);
program
  .command('help [command...]')
  .description('Display help for a command. Pass multiple words to drill into subcommands (e.g. `dap-cli help breakpoints set`).')
  .action((commandPath: string[] | undefined) => {
    const segments = Array.isArray(commandPath) ? commandPath : [];
    if (segments.length === 0) {
      program.outputHelp();
      return;
    }
    let current: Command = program;
    const matched: string[] = [];
    for (const segment of segments) {
      const next = current.commands.find(child => child.name() === segment);
      if (!next) {
        const knownPath = matched.length === 0 ? 'dap-cli' : `dap-cli ${matched.join(' ')}`;
        const requestedPath = `dap-cli ${segments.join(' ')}`;
        const message = `Unknown help target: ${requestedPath}. \`${segment}\` is not a subcommand of \`${knownPath}\`.`;
        // Render the parent's help so the user sees what IS available, then
        // fail through commander's exitOverride so main.ts emits a real
        // usage_error envelope (NOT a help-dispatch one).
        current.outputHelp({ error: true });
        const error = new Error(message);
        error.name = 'CommanderError';
        (error as Error & { code: string; exitCode: number }).code = 'commander.unknownCommand';
        (error as Error & { code: string; exitCode: number }).exitCode = 2;
        throw error;
      }
      matched.push(segment);
      current = next;
    }
    current.outputHelp();
  });
```

Notes for implementer:
- `program.helpCommand(false)` MUST come before the `program.command('help ...')` registration; otherwise commander registers both and the variadic one will not be reachable.
- The thrown `CommanderError`-shaped error with `code: 'commander.unknownCommand'` and `exitCode: 2` is already handled by the existing `isCommanderError` branch in `main.ts`, which converts it to a `usage_error` envelope. The Task 1 fix to `isCommanderHelp` only short-circuits `code === 'commander.help'` and `exitCode === 0`, so this unknown-path error correctly falls through to the envelope path.
- Do NOT change `addHelpText('after', ...)` — examples should still appear after the categorized command list.
- Import `Command` type if not already imported at the top of the file (it is — `import { Command } from 'commander';`).
