<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Test runner → local .NET process | Tests start debuggee processes |
| Attach request → process table | Test passes a PID to NetCoreDbg |
| Adapter disconnect → process cleanup | Wrong cleanup can kill unrelated processes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-21-11 | Elevation | attach test | mitigate | Attach only to a process spawned by the test from `simple-csharp-attach`; gate with `DAP_CLI_RUN_NETCOREDBG_ATTACH_SMOKE=1`. |
| T-21-12 | DoS | process cleanup | mitigate | Disconnect with `terminateDebuggee:false`, assert process survives, then terminate exact owned PID only. |
| T-21-13 | Repudiation | missing dotnet | mitigate | If host `dotnet` is absent, run the focused test in an official .NET SDK container when Docker is available; otherwise record a blocked diagnostic, not a false pass. |
| T-21-14 | Information Disclosure | variables/evaluate | accept | Fixtures contain no secrets; inspect only deterministic locals `left`, `right`, `result`. |
| T-21-14b | Tampering | `.dll` inference | mitigate | Add `.dll` inference only after this plan's real NetCoreDbg DLL launch test proves built DLL launch works. Do not add `.csproj` inference. |
</threat_model>
