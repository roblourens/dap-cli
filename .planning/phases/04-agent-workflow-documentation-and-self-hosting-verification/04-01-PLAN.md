**# Agent Workflows**

**## Poll-Then-Inspect Loop**
Explain the core pattern per AGNT-05:
1. Poll `status --name <session>` to check execution state (running, stopped, terminated)
2. Poll `events --name <session> --after-cursor 0 --limit 20` to see recent events
3. If stopped, inspect: `threads` → `stack --thread-id` → `scopes --frame-id` → `variables --variables-reference`
4. Act: `evaluate`, `continue`, `step-over`, etc.
5. Repeat from step 1

**Important:** DAP object references (frameId, variablesReference) are valid only for the current suspended state. After `continue` or other execution commands, reacquire references through `threads`/`stack`/`scopes`/`variables` on the next pause.

**## Breakpoint Workflow**
```bash
dap-cli breakpoints set --source src/app.js --line 10 --name demo
dap-cli breakpoints list --name demo  # verify breakpoints

dap-cli stack --thread-id 1 --name demo

```

**# Playwright Interop**

**## Overview**
Playwright drives the browser UI, dap-cli controls and inspects the debugger state. Use polling commands to coordinate.

**## Setup Order**
1. Start dap-cli controller
2. Launch js-debug with Chrome target and set breakpoints
3. Verify debugger is ready through `status` and `events`
4. Trigger Playwright actions (which will hit breakpoints)
5. Poll for stopped events and inspect state
6. Continue execution or step through code
7. Clean up

**## Example: Web App Debugging**

**Terminal 1: Establish debugger state**
```bash
dap-cli start
dap-cli launch \
  --adapter js-debug \
  --type chrome \
  --url http://localhost:3000 \
  --runtime-executable "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --runtime-args "--headless=new" \
  --name web-demo

dap-cli breakpoints set --source src/app.js --line 15 --name web-demo
dap-cli status --name web-demo  # verify initialized
dap-cli events --name web-demo --limit 5  # check initialized event
```

**Terminal 2: Drive UI actions**
```bash
npx playwright test tests/web-demo.spec.ts --project=chromium --workers=1
```

**Terminal 1: Poll and inspect**
```bash
dap-cli events --name web-demo --after-cursor 0 --limit 20  # check for stopped event
dap-cli threads --name web-demo
dap-cli stack --thread-id 1 --name web-demo
dap-cli scopes --frame-id <id> --name web-demo
dap-cli variables --variables-reference <ref> --name web-demo
dap-cli evaluate --expression "document.title" --frame-id <id> --name web-demo
dap-cli continue --thread-id 1 --name web-demo
```

**## Playwright Test Coordination**
In a Playwright test, you can shell out to dap-cli commands between UI actions:
```typescript
await page.goto('http://localhost:3000');
// Shell: dap-cli events --name web-demo --after-cursor 0
await page.click('#submit-button');
// Shell: dap-cli events --name web-demo --after-cursor N
// Shell: dap-cli stack --thread-id 1 --name web-demo
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| docs → user shell | Markdown documentation includes shell command examples that users may copy directly |
| docs examples → localhost services | Examples reference localhost URLs and fixture paths that users control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-docs-01 | Tampering | README.md / docs command examples | mitigate | Use only localhost/simple fixture paths in examples; do not include external URLs or untrusted paths. Examples should reference tests/fixtures/* which are under repository control. |
| T-04-docs-02 | Information Disclosure | Example JSON output in docs | accept | Example JSON output shows only fixture data (simple variables, stack frames from known code) with no secrets or PII. Risk accepted as educational value outweighs minimal exposure. |
| T-04-docs-03 | Elevation of Privilege | Shell command examples | mitigate | Command examples do not use shell interpolation of untrusted input. Fixed literal paths and option values only. No `$(...)` or backtick expansion in examples. |
| T-04-shell-04 | Injection | Playwright interop shell examples | mitigate | Examples show separate Terminal 1/Terminal 2 workflows with fixed literal commands, not dynamically constructed from app output. Docs must not suggest piping app output directly into shell commands without validation. |
</threat_model>
