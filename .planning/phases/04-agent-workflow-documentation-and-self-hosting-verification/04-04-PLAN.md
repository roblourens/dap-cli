Implement full Playwright + dap-cli interop scenario in `tests/integration/playwrightInterop.test.ts` that satisfies AGNT-04 and TEST-07. The scenario:

**Setup phase:**
1. Start dap-cli controller (done in beforeAll from Task 0)
2. Serve `tests/fixtures/simple-chrome-page/index.html` via local HTTP server or file:// URL
3. Launch js-debug with Chrome target pointing to the page URL
4. Set breakpoint in `tests/fixtures/simple-chrome-page/app.js` at line 2 (inside `calculate` function)
5. Verify debugger ready: poll `status`, check `events` for initialized

**Interaction phase:**
6. Use Playwright API to navigate to the page: `page.goto(url)`
7. Verify page loaded: `await page.waitForSelector('#result')`
8. Trigger breakpoint: `await page.evaluate(() => window.calculate(2, 3))`
   (Or trigger via DOM interaction if calculate() is wired to a button)

**Inspection phase:**
9. Poll dap-cli for stopped event: `dap-cli events --after-cursor 0 --limit 20`
10. Verify stopped event present and reason is 'breakpoint'
11. Get threads: `dap-cli threads --name web-demo`
12. Get stack: `dap-cli stack --thread-id 1 --name web-demo`
13. Verify stack frame shows `calculate` function and correct source path suffix
14. Get scopes: `dap-cli scopes --frame-id <id> --name web-demo`
15. Get variables: `dap-cli variables --variables-reference <ref> --name web-demo`
16. Verify local variables `left=2, right=3` present

**Resume phase:**
17. Continue execution: `dap-cli continue --thread-id 1 --name web-demo`
18. Verify Playwright page shows result: `await expect(page.locator('#result')).toHaveText('5')`

**Cleanup:**
19. Close Playwright page
20. Stop dap-cli session: `dap-cli stop --name web-demo` or `cleanup` (done in afterAll)

Use single-worker deterministic execution (Playwright API is already sequential in test body, no parallel workers needed). Use existing `runCli` and `parseEnvelope` utilities from `tests/helpers/runCli.ts`.

**If file:// URL issues arise with js-debug:** Start a simple local HTTP server in beforeAll (using Node http module or Vitest preview server if available) and serve fixtures over http://localhost:<port>. Document the approach in test comments.

**Error handling:**
- If js-debug fails to attach to Chrome, provide diagnostic: check Chrome path, headless mode, user-data-dir conflicts.
- If breakpoint never hits, diagnostic: verify source path, breakpoint line number, and that page actually executed calculate().
- Keep test deterministic: no race conditions between Playwright action and dap-cli polling. Add small delays if needed, or poll events with retry logic.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Playwright → browser | Playwright controls browser via DevTools protocol over localhost |
| dap-cli → js-debug → browser | js-debug attaches to browser debug port (localhost) |
| test harness → network | Exploratory scenarios may access local HTTP server or file:// URLs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-browser-race-01 | Denial of Service | tests/integration/playwrightInterop.test.ts | mitigate | Use deterministic single-worker execution. Playwright actions occur only after dap-cli debugger setup confirmed via `status` and `events` polling. Add polling retry logic if needed to avoid race between breakpoint and UI trigger. |
| T-04-session-cleanup-02 | Denial of Service | playwrightInterop test cleanup | mitigate | Test afterAll must close Playwright browser and stop dap-cli controller. Verify no orphaned Chrome or adapter processes after suite. |
| T-04-network-fetch-03 | Spoofing | Exploratory scenarios accessing network | accept | Exploratory scenarios may access localhost HTTP servers or file:// URLs under user/test control. No external network fetch from untrusted sources in automated tests. Risk accepted for local testing. |
| T-04-backlog-exposure-04 | Information Disclosure | .planning/BACKLOG.md | accept | Backlog may reference internal implementation details or limitations. File is under repository control and not exposed externally. Risk accepted as normal planning artifact. |
</threat_model>
