<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public GitHub repositories → local workstation | External source, scripts, and project commands are untrusted. |
| external project runtime → debugger/logs | Debugging can expose project paths, args, and locals into evidence artifacts. |
| cleanup logic → local process table/filesystem | Validation must remove only phase scratch/processes it owns. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-05-01 | Tampering / Elevation | executing external project scripts | mitigate | Screen README/go.mod/Makefiles/hooks first; reject secrets, privilege, Docker, cloud, opaque hooks, and record every command before execution. |
| T-20-05-02 | Information Disclosure | result transcripts and debugger variable output | mitigate | Capture only evidence necessary for debugging conclusions, keep it workspace-local, and avoid copying credentials/private machine data into ledgers. |
| T-20-05-03 | Denial of Service | heavyweight or looping external projects | mitigate | Prefer small deterministic repos, use scenario-specific cleanup, and block high-cost candidates instead of forcing them. |
| T-20-05-04 | Repudiation | unverifiable external result claims | mitigate | Require repo URL, commit SHA, commands, breakpoint, transcript/evidence, cleanup, and result classification for each attempt. |
</threat_model>
