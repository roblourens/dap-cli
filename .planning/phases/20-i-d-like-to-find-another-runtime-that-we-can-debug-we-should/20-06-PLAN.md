Run the agent-hardening loop the user asked for: define fresh-agent Go/Delve tasks, collect exact confusion/failure evidence, classify gaps, fix or route them, and retry the scenarios until the remaining state is explicit.

Output: Scenario matrix, results/reruns ledger, hardening-gap ledger, and an execution-ready bridge into any code/docs gap closure plus later UAT smoke.
</objective>

| Boundary | Description |

| external validation evidence → hardening conclusions | Reports can misclassify product gaps unless evidence is retained. |
| test/external-agent evidence → later UAT status | Automation must not erase the repository's separate hand-driven terminal smoke requirement. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-06-01 | Tampering | fresh-agent prompts using external repo material | mitigate | Scenario prompts reference screened ledgers and repo-owned docs, never unreviewed external README commands copied blindly. |
| T-20-06-02 | Repudiation | confusion/failure reports | mitigate | Fixed report shape requires result, what worked, what failed, confusion, ergonomic issues, evidence, and cleanup status; reruns append rather than overwrite. |
| T-20-06-03 | Denial of Service | repeated retries of blocked scenarios | mitigate | Classify candidate/environment/unsafe blockers explicitly and stop forcing them; rerun only actionable product/docs scenarios after repair. |
| T-20-06-04 | Information Disclosure | agent transcripts/logs | mitigate | Keep transcripts workspace-local and record only evidence needed to reproduce Go/Delve behavior, following the external-ledger privacy screen. |
| T-20-06-05 | Process/Lifecycle | attach/disconnect scenarios | mitigate | Scenario G-05 and hardening classification must reuse Plan 20-03's explicit attach/disconnect lifecycle contract and require cleanup verification. |
</threat_model>
