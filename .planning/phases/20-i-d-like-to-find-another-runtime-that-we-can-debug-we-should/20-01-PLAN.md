<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| setup command → official Delve release | A local CLI tool selects and downloads executable adapter content from a remote release source. |
| dap-cli → spawned `dlv dap` server | dap-cli launches a debugger process and opens a local DAP socket. |
| local filesystem → descriptor resolution | Provisioned binaries and PATH commands are executable inputs chosen before a session starts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01-01 | Spoofing / Tampering | `scripts/setup-adapters.ts` Delve provisioning | mitigate | Pin the release/version and official source in `20-ADAPTER-SELECTION.md`; implement checksum verification when selected by the decision artifact or record the explicit trust boundary and concrete blocker before execution proceeds. |
| T-20-01-02 | Information Disclosure | Delve DAP listen address | mitigate | Descriptor args must use `--listen=127.0.0.1:${port}` and tests assert no `0.0.0.0` binding appears. |
| T-20-01-03 | Elevation / Tampering | PATH `dlv` precedence | mitigate | Setup/descriptor diagnostics report the chosen path and candidate locations; tests cover missing-runtime failure instead of silently executing an unidentified command. |
| T-20-01-04 | Denial of Service | Unsupported platform provisioning | mitigate | Platform mapping fails clearly before bogus downloads or repeated retries; dry-run remains cheap and testable. |
</threat_model>
