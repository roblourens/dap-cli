  <name>Task 1: Provision a package.json boundary for js-debug adapter to isolate it from ancestor ESM package scopes</name>
  <files>scripts/setup-adapters.ts, src/adapters/builtins/jsDebug.ts</files>
  <read_first>
    - scripts/setup-adapters.ts (setupJsDebug function around line 40-85)
    - src/adapters/builtins/jsDebug.ts (resolveDefaultJsDebugPath and descriptor creation)
    - .planning/phases/07-hardening-bug-discovery-and-exploratory-smoke-testing/07-UAT.md (GAP-07-03 reproduction and error details: "Dynamic require of 'fs' is not supported")
  </read_first>
  <action>
The root cause of GAP-07-03 is that Node's package-scope resolution treats js-debug's `.js` files (CommonJS with dynamic `require()` calls) as ESM when they are under a parent package tree with `"type": "module"`. The error "Dynamic require of 'fs' is not supported" happens because ESM modules cannot use dynamic `require()`.

Fix by provisioning a package.json boundary for the js-debug adapter:

In `scripts/setup-adapters.ts` `setupJsDebug` function, after extracting the js-debug tarball and verifying entrypoint existence:
1. Create a `package.json` file at `$adaptersDir/js-debug/package.json` with content `{"type": "commonjs"}`.
2. Write the file using `fs.writeFile(path.join(jsDebugDir, 'package.json'), '{"type": "commonjs"}\n', 'utf8')`.
3. This tells Node that everything under `js-debug/` should be treated as CommonJS, even if an ancestor directory has `"type": "module"`.

Why this works:
- Node's package-scope resolution walks up the directory tree until it finds a `package.json` with a `type` field.
- By placing `{"type": "commonjs"}` at the adapter root, we stop the upward walk before reaching the repo's `"type": "module"` package.json.
- js-debug's own code does not have a `package.json` at its root (it's extracted from a tarball), so we must add one.

Do NOT change the adapter spawn cwd or command — the descriptor and process spawning logic should remain unchanged. The package.json boundary is sufficient and less invasive than cwd overrides.

Verify the fix:
- After provisioning, `ls $DAP_CLI_HOME/adapters/js-debug/package.json` should exist with `{"type": "commonjs"}`.
- Re-run the GAP-07-03 reproduction (set `DAP_CLI_HOME=$PWD/tmp/phase-07-local-dap-home`, provision adapters, launch js-debug pwa-node session) and verify it no longer crashes with the ESM dynamic require error.
  </action>
  <acceptance_criteria>
    - `grep -A5 "setupJsDebug" scripts/setup-adapters.ts | grep -q "package.json"` (provisioning writes package.json boundary)
    - `npm run build` succeeds
    - `npx tsx scripts/setup-adapters.ts` (or manual run) provisions js-debug with package.json boundary
  </acceptance_criteria>
  <verify>
    <automated>npm run build</automated>
  </verify>
  <done>js-debug adapter provisioning creates a package.json boundary that isolates the adapter from ancestor ESM package scopes.</done>
