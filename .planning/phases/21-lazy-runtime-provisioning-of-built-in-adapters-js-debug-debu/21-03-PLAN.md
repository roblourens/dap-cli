<interfaces>
Locked decisions referenced by this plan:
- D-11 — NO `spawnSync('tar' | 'unzip', ...)` anywhere; including `scripts/setup-adapters.ts`.
- D-13 — `dap-cli setup-adapters` is a user-facing CLI subcommand (not just an npm script).
- D-14 — `setup-adapters` confirms ONCE for ALL adapters; per-adapter prompts are not the default behavior.
- D-18 — `--yes` / `DAP_CLI_ASSUME_YES=1` pre-consent applies to `setup-adapters` too.

Subcommand shape:

```
dap-cli setup-adapters [options]

Options:
  --adapter <id>      Install only a single adapter (js-debug | debugpy | delve).
                      Default: install all three.
  --yes, -y           Skip the confirmation prompt (inherits from program-level flag).
  --json              Emit machine-readable per-adapter status (existing JSON output mode).
```

Behavior:
- With no `--adapter`: enumerate `['js-debug', 'debugpy', 'delve']`. For adapters that already have cache + consent marker, skip silently (or log "already installed" in human mode). For adapters needing install: emit ONE consolidated `confirm()` describing all pending installs (e.g. "Install vscode-js-debug 1.117.0, debugpy 1.8.20, and delve v1.26.3 into ~/.dap-cli/adapters/ (~30MB total)?"). Then loop and invoke `provisionAdapter(id, ctx)` with a flag that suppresses each provisioner's own internal prompt (`assumeYes=true` for the inner call once the outer prompt has been answered yes).
- With `--adapter X`: prompt only for X (or skip prompt if already installed); install only X.
- Output: human mode prints "Installing js-debug 1.117.0...", "Installed js-debug 1.117.0 (1.2s)", etc. JSON mode emits a final `{ adapters: [{ id, version, status: 'installed'|'cached'|'failed', installRoot, error? }] }`.
- Failure of one adapter does NOT abort the others by default. Each error is captured and reported at the end. Exit code is non-zero if any adapter failed.

`scripts/setup-adapters.ts` rewrite:
- Becomes a 10-15 line file that calls the same `runSetupAdaptersAction(...)` exported from `src/cli/commands/setupAdapters.ts`.
- Removes all current `setupJsDebug`/`setupDebugpy`/`setupDelve` functions, the `spawnSync('tar', ...)` call, and the inline checksum constants.
- Kept reason: backwards compatibility with `npm run setup-adapters`, which Rob's CI / docs may already reference; users running it get the same UX as the CLI subcommand.

```ts
#!/usr/bin/env node --experimental-strip-types
// Developer-facing wrapper around `dap-cli setup-adapters`.
// All provisioning logic lives in src/adapters/provision; this script exists
// so `npm run setup-adapters` keeps working and so contributors can warm the
// cache without building the CLI bundle first.

import { runSetupAdaptersAction } from '../src/cli/commands/setupAdapters.ts';
import { resolveAssumeYes } from '../src/cli/confirm.ts';

async function main(): Promise<void> {
  const args = process.argv.slice(2);
  const adapterFlag = args.indexOf('--adapter');
  const adapter = adapterFlag >= 0 ? args[adapterFlag + 1] as 'js-debug' | 'debugpy' | 'delve' : undefined;
  const assumeYes = resolveAssumeYes(args.includes('--yes') || args.includes('-y'), process.env);
  const result = await runSetupAdaptersAction({
    adapter,
    assumeYes,
    env: process.env,
    stdin: process.stdin,
    stderr: process.stderr,
    stdout: process.stdout,
    json: args.includes('--json'),
  });
  const anyFailed = result.adapters.some(a => a.status === 'failed');
  if (anyFailed) process.exit(1);
}

main().catch(err => {
  process.stderr.write(`${err?.message ?? err}\n`);
  process.exit(1);
});
```
