Locked decisions referenced by this plan:
- D-06 — `DAP_CLI_ASSUME_YES=1` / `--yes` bypasses consent. Used as the belt-and-suspenders env in adapter tests that intentionally exercise the provisioner path (none in this plan — we short-circuit via D-20 instead).
- D-12 — `DAP_CLI_ADAPTERS_DIR` (and the `DAP_CLI_HOME`-derived default in `getDapCliAdaptersDir`) lets a test point at a per-test temp dir. We rely on the `DAP_CLI_HOME` form because `createTempDapCliEnv` already populates it.
- D-20 — `.consent-<version>` is a download-record. Pre-staging both the entrypoint AND the consent marker via `provisionAdapterIntoTempEnv` (which symlinks the whole `<adapter>/` directory from the host's `~/.dap-cli/adapters/<id>/`) short-circuits the resolver's provisioner-invocation path BEFORE `confirm()` is reached.

Established helpers (DO NOT reinvent):
- `src/testing/tempEnv.ts::createTempDapCliEnv(prefix)` → `{ dapCliHome, env, cleanup }`. Already wrapped by `tests/helpers/runCli.ts::createCliTestEnv`, which the failing tests already use.
- `src/testing/tempEnv.ts::provisionAdapterIntoTempEnv(target, adapterId)` → symlinks `~/.dap-cli/adapters/<id>/` into `<target.dapCliHome>/adapters/<id>/`. Used today by `tests/integration/jsDebugAdapter.test.ts` (5 call sites) and `tests/integration/playwrightInterop.test.ts` (3 call sites). Throws an actionable error naming `npm run setup-adapters` when the source adapter is missing — same precondition as `linkProvisionedJsDebug` in `tests/integration/selfHosting.test.ts:245`.

Why `process.env.DAP_CLI_HOME` must be temporarily mutated (not just `testEnv.env` passed to a helper):

The failing tests construct `new AdapterRegistry()` and call `.resolve('debugpy' | 'delve')` directly (NOT through `runCli`). `resolveDefaultDebugpyPythonPath` / `resolveDefaultDelvePath` read `env = process.env` by default; the registry has no env-injection seam. The minimal-blast-radius fix is to assign `process.env.DAP_CLI_HOME = testEnv.dapCliHome` in `beforeEach` and restore the prior value in `afterEach`, mirroring the save-and-restore pattern already in `tests/helpers/runCli.ts:setOptionalEnv` (lines 162-169). Vitest runs tests in a file sequentially within one worker process, so save/restore per `beforeEach`/`afterEach` is sufficient.

Non-goal: do NOT add an env-injection parameter to `AdapterRegistry` or the descriptor factories. That would be a production-API change for a testing concern, and the env mutation pattern is already established repo-wide.

Cluster B doc-fix justification:

The 21-06 SUMMARY explicitly named "lowercase adapter ID" as the convention but DID NOT call out that Phase 20's product-name mentions of `Delve` would be lost. The test in `tests/integration/docsValidation.test.ts:73` is the canonical signal that this content matters — the test exists precisely to prevent silent drift on the Phase 20 docs. Loosening the test to `.toLowerCase().contains('delve')` would hide future regressions where the entire Delve section is accidentally deleted. The correct fix is a one-sentence addition to the Overview section naming the product (e.g., upgrading the existing `delve` mention to "**Delve** (`delve`)"). One ASCII byte of doc, full test coverage retained.

After Task 1 + Task 2 commit, run `npm test` end-to-end. The selfHosting flake (`dap-cli debugs simple-node-app fixture with stop-on-entry inspection`) hypothesis from the gap doc is "cross-test interference from parallel adapter dir contention." Clusters A's per-test adapter dir isolation MAY transitively fix this — the failing test currently shares the user's real `~/.dap-cli/adapters/js-debug/` via `linkProvisionedJsDebug` (selfHosting.test.ts:33), and parallel tests in the suite previously mutated that shared dir. If the flake persists, the fallback is to bump the implicit 5s test timeout to 30s (matching `delveAdapter.test.ts`'s 60_000 and other launch-cycle integration tests), with a one-line comment naming the gap.
