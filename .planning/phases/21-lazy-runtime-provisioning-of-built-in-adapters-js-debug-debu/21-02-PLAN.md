<objective>
Build the three per-adapter provisioners (js-debug, debugpy, delve) on top of the 21-01 primitives, and wire each built-in descriptor factory so that a missing binary triggers consent + download + atomic install rather than throwing `*_not_found`. After this plan, `dap-cli launch --config "TypeScript Mini"` on a fresh machine prompts once, installs js-debug into `~/.dap-cli/adapters/js-debug/`, and resolves a working descriptor.

Purpose: This plan delivers the user-facing behavior the whole phase exists for. The 21-01 primitives are inert until they're composed into per-adapter flows; this plan composes them and decides which artifacts each adapter downloads.

Output: `provisionAdapter()` API, three provisioner modules, embedded checksum tables, a maintainer helper for regenerating checksums, and rewired descriptor factories.
</objective>

Public API this plan establishes (consumed by 21-03 `setup-adapters` subcommand):

```ts
// src/adapters/provision/index.ts
export interface ProvisionContext {
  env: NodeJS.ProcessEnv;        // injected for tests; defaults to process.env
  assumeYes: boolean;            // from resolveAssumeYes()
  adaptersDir: string;           // from getDapCliAdaptersDir(env)
  stdin?: NodeJS.ReadStream;     // for confirm()
  stderr?: NodeJS.WriteStream;
}

export interface ProvisionResult {
  adapterId: 'js-debug' | 'debugpy' | 'delve';
  version: string;
  installRoot: string;           // <adaptersDir>/<adapterId>
  entrypoint: string;            // absolute path to the executable used by the descriptor
  fromCache: boolean;            // true if no download happened (warm cache + consent marker present)
}

export async function provisionAdapter(
  id: 'js-debug' | 'debugpy' | 'delve',
  ctx: ProvisionContext,
): Promise<ProvisionResult>;
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Network → downloaded archives | Archives from `github.com` (or proxy) become local executable code (`dapDebugServer.js`, `dlv`, debugpy wheel). |
| File system → executable bit on `dlv` | Provisioning sets +x on a downloaded binary. |
| Process → python3 + pip | `python3 -m venv` and `pip install` execute arbitrary code from PyPI's debugpy package. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-02-01 | Tampering | js-debug tar.gz integrity | mitigate | SHA-256 verify against embedded `JS_DEBUG_CHECKSUMS` per D-21; mismatch throws `provision_checksum_mismatch` and aborts before staging-to-canonical rename. |
| T-21-02-02 | Tampering | delve archive integrity | mitigate | Same as T-21-02-01 against `DELVE_CHECKSUMS`. |
| T-21-02-03 | Tampering | debugpy wheel integrity | transfer | pip handles wheel signature/hash verification against PyPI; trust boundary is the user's `pip` + PyPI. Document in 21-06 docs that the user can pin via `--index-url` if they need stricter control. |
