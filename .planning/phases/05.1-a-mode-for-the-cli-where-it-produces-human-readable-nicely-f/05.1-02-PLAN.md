<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Shell env/args -> Commander root options | `--human`, `--no-human`, and `DAP_CLI_HUMAN` select presentation. |
| Commander/CLI -> automation stdout | Existing automation expects stdout JSON by default and empty stderr for handled failures. |
| Command payload flags -> DAP/controller request bodies | Existing `--json` flags carry untrusted JSON payloads, not presentation mode. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.1-06 | Tampering | `DAP_CLI_HUMAN` handling in `main`/`program` | mitigate | CLI flags override env; invalid env yields handled `invalid_output_mode_env` instead of silent mode changes. |
| T-05.1-07 | Denial of Service | Default command output | mitigate | Tests assert default success/failure remains one JSON envelope on stdout; no TTY auto-detection. |
| T-05.1-08 | Spoofing | Core DAP `--json` options | mitigate | Keep `--json <json>` definitions unchanged and add regression tests around payload parsing. |
| T-05.1-09 | Information Disclosure | Human failures for controller/session/core commands | mitigate | OutputWriter uses Plan 01 renderer that only displays fields already present in JSON error payload. |
| T-05.1-10 | Tampering | Terminal control sequences in core command data | mitigate | Human success/failure paths route through `sanitizeForTerminal` from Plan 01. |
</threat_model>
