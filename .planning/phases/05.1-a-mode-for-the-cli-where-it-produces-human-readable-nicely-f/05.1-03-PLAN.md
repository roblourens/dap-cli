<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Generated DAP payload flags -> controller request | `--json` carries untrusted DAP arguments for generated/raw requests. |
| Adapter response data -> human renderer | DAP bodies may contain arbitrary strings, source text, stderr, or evaluated values. |
| Renderer selection -> user interpretation | Human summaries could omit or overstate important fields. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.1-11 | Spoofing | Generated command `--json` flags | mitigate | Regression tests prove `--json` remains payload input while root `--human`/`--no-human` selects output mode. |
| T-05.1-12 | Tampering | `humanOutput.ts` renderers | mitigate | Sanitize terminal controls in every string field before writing to stdout. |
| T-05.1-13 | Information Disclosure | Curated renderers | mitigate | Render only data already supplied to JSON envelopes; no additional file reads, env dumps, or stack traces. |
| T-05.1-14 | Denial of Service | Large generated DAP bodies | mitigate | Use bounded `util.inspect` depth and fallback rather than recursive custom traversal without limits. |
| T-05.1-15 | Repudiation | Human summaries of warnings/errors | mitigate | Events warnings and failure diagnostics are displayed explicitly with code/category in failure mode. |
</threat_model>
