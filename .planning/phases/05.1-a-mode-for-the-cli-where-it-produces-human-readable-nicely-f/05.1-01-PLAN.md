<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args/env -> output-mode resolver | Untrusted shell state selects JSON or human presentation. |
| Adapter/controller data -> human terminal | External debug data becomes terminal-visible text. |
| Existing JSON writer -> new writer abstraction | Automation contract depends on JSON mode delegating without mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.1-01 | Tampering | `resolveOutputMode` | mitigate | Accept only explicit `DAP_CLI_HUMAN` values; invalid values raise `invalid_output_mode_env`; CLI booleans override env. |
| T-05.1-02 | Tampering | `sanitizeForTerminal` | mitigate | Replace ESC/C0/C1 controls before human rendering diagnostics/data, preventing terminal control sequence injection. |
| T-05.1-03 | Denial of Service | `createOutputWriter` JSON mode | mitigate | JSON mode delegates to existing `writeJsonSuccess`/`writeJsonFailure`; tests preserve one-envelope output for automation. |
| T-05.1-04 | Information Disclosure | `renderHumanFailure` | mitigate | Render only fields already present in JSON error payload; never add stack traces, process env, or hidden controller internals. |
| T-05.1-05 | Spoofing | Existing command `--json` payload flags | accept | This foundation does not touch command option parsing; collision protection is enforced in later command-wiring tests. |
</threat_model>
