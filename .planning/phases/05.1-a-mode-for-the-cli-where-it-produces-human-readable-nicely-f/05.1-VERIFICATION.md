## What I verified (must-haves → evidence)

- **Default JSON remains the contract (D-01 / validation map 05.1-01-01)**: JSON envelope writers remain in [src/cli/output.ts](src/cli/output.ts) and are still used as the JSON path. Evidence: `writeJsonSuccess` / `writeJsonFailure` in [src/cli/output.ts](src/cli/output.ts) and tests asserting one newline-terminated JSON envelope in [tests/cli/jsonOutput.test.ts](tests/cli/jsonOutput.test.ts). `main` uses `createOutputWriter` but JSON delegation is implemented in [src/cli/outputWriter.ts](src/cli/outputWriter.ts).

- **Global `--human` / `--no-human` and env `DAP_CLI_HUMAN` (D-02..D-04 / validation map tasks)**: Commander root options exist in [src/cli/program.ts](src/cli/program.ts) and mode resolution is implemented in [src/cli/outputMode.ts](src/cli/outputMode.ts). Tests validating CLI precedence, env parsing, and invalid env behavior are in [tests/cli/humanOutput.test.ts](tests/cli/humanOutput.test.ts) and integration tests in [tests/cli/jsonOutput.test.ts](tests/cli/jsonOutput.test.ts).

- **Command-level `--json` remains payload input (D-05 / validation map 05.1-03-01, 05.1-02-01)**: Payload parsing is handled by `parseJsonOption` in [src/cli/commands/jsonOptions.ts](src/cli/commands/jsonOptions.ts) and `--json` flags remain present on `launch`/`attach`/`request` and generated commands in [src/cli/commands/dapCore.ts](src/cli/commands/dapCore.ts) and [src/cli/commands/dapGenerated.ts](src/cli/commands/dapGenerated.ts). Regression tests showing `launch --json` errors and generated command payload semantics are in [tests/cli/jsonOutput.test.ts](tests/cli/jsonOutput.test.ts) and [tests/cli/dapGeneratedCommands.test.ts](tests/cli/dapGeneratedCommands.test.ts).

- **Mode-aware output writer wiring (artifact & key-links)**: The OutputWriter abstraction and wiring exist in [src/cli/outputWriter.ts](src/cli/outputWriter.ts). All major command groups (controller, sessions, core DAP, generated, aliases) receive and use the OutputWriter: [src/cli/commands/controller.ts](src/cli/commands/controller.ts), [src/cli/commands/sessions.ts](src/cli/commands/sessions.ts), [src/cli/commands/dapCore.ts](src/cli/commands/dapCore.ts), [src/cli/commands/dapGenerated.ts](src/cli/commands/dapGenerated.ts), and [src/cli/commands/dapAliases.ts](src/cli/commands/dapAliases.ts). Program-level creation is in [src/cli/program.ts](src/cli/program.ts). Tests exercise the wiring (see `tests/cli/*` listed above).

- **Deterministic sanitized human renderers (Plan 03 / validation map 05.1-04-01)**: Curated plain-text renderers and sanitizer are implemented in [src/cli/humanOutput.ts](src/cli/humanOutput.ts). They use bounded `util.inspect` options and replace control characters (tab/newline allowed) via `sanitizeForTerminal`. Unit tests for renderers and sanitization are in [tests/cli/humanOutput.test.ts](tests/cli/humanOutput.test.ts).

- **Polished human presentation (Plan 06 user feedback)**: Human output omits noisy `Command:` and `Timestamp:` metadata, uses bordered tables for table-like results, and applies terminal-aware semantic ANSI styling while respecting `NO_COLOR`. Regressions are in [tests/cli/humanOutput.test.ts](tests/cli/humanOutput.test.ts), [tests/cli/jsonOutput.test.ts](tests/cli/jsonOutput.test.ts), and [tests/cli/sessionCommands.test.ts](tests/cli/sessionCommands.test.ts).

- **Handled failures preserved & routed through writer**: `main` uses `createOutputWriter` and `selectRenderableError` to ensure mode-resolution failures are surfaced correctly; see [src/cli/main.ts](src/cli/main.ts) and tests in [tests/cli/jsonOutput.test.ts](tests/cli/jsonOutput.test.ts).
