# Set up npm publishing via GitHub Actions

## Description

The package (`@roblourens/dap-cli`) is configured for npm (`bin`, `files`,
`publishConfig.access: public`, `prepublishOnly: npm run check`) but the repo
has no `.github/workflows/` and no release automation. Releases are entirely
manual today.

Add a single GitHub Actions workflow that publishes to npm when a GitHub
Release is published, with provenance enabled and a tag-vs-`package.json`
version sanity check so a mistagged release fails fast rather than uploading a
wrong version.

## Decisions (defaults — no `--discuss` was used)

- **Trigger:** `on: release: published` plus `workflow_dispatch` (manual
  re-run from the Actions tab if a publish fails after the release is already
  created). Release-driven keeps GitHub's UI as the source of truth for what
  "shipped".
- **Auth:** classic `NPM_TOKEN` repo secret. Documenting OIDC trusted
  publishing is out of scope — the user can swap later by deleting the
  `NODE_AUTH_TOKEN` env and registering the repo on npmjs.com.
- **Provenance:** `--provenance` flag. Requires `id-token: write` permission
  on the job. Works with both `NPM_TOKEN` and OIDC.
- **Version source of truth:** `package.json` `version` field. Workflow does
  NOT bump versions. It DOES verify the release tag (`v<x.y.z>`) matches
  `package.json` to prevent mistagged publishes.
- **Quality gate:** `npm run check` (typecheck + lint + tests + build +
  packaging tests). Already wired as `prepublishOnly`, but running it
  explicitly in CI makes the failure visible in the Actions log instead of
  buried in npm output.
- **Node version:** 22 (matches `engines.node: ">=22"`).
- **Scope:** Publish workflow only. No PR-CI workflow, no auto-version-bump,
  no changelog generation. Keep ceremony minimal.

## Tasks

### Task 1: Add publish workflow

**Files**

- `.github/workflows/publish.yml` (new)

**Action**

Create `.github/workflows/publish.yml`:
   - Trigger on `release: { types: [published] }` and `workflow_dispatch`.
   - Top-level `permissions`: `contents: read`. Job-level adds
     `id-token: write` for provenance.
   - Single job `publish` on `ubuntu-latest`:
     - `actions/checkout@v4`
     - `actions/setup-node@v4` with `node-version: 22`,
       `registry-url: https://registry.npmjs.org`, `cache: npm`
     - `npm ci`
     - Tag-vs-version guard: when triggered by `release`, compare
       `github.event.release.tag_name` (stripped of leading `v`) to
       `package.json` `version`. Fail the job with a clear message if they
       differ. Skip the guard on `workflow_dispatch` (manual recovery).
     - `npm run check` (runs typecheck, lint, tests, build, packaging tests)
     - `npm publish --provenance --access public` with
       `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}`

Release-process docs (NPM_TOKEN setup, per-release steps) live in the
quick-task SUMMARY.md, not in the user-facing README.

**Verify**

- `cat .github/workflows/publish.yml` — workflow exists, parses as YAML.
- `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/publish.yml'))"`
  parses cleanly.

**Done**

- `.github/workflows/publish.yml` exists and triggers on
  `release: published` + `workflow_dispatch`.
- Workflow uses Node 22, runs `npm ci` + `npm run check` + `npm publish
  --provenance --access public`.
- Tag-vs-`package.json` version guard present and active on `release`
  trigger.
- `id-token: write` permission set so provenance signing works.
- No other workflows added (PR CI, version bumping, changelog are out of
  scope).
